6. lightsail.bucket.public_access

Finding
1 of 2 buckets are private with no public object overrides
Controls
A.8.3
Affected (non compliant)
  • bucket: static-site; public read: True; allow public object overrides: False
How to fix
In the Lightsail console open the bucket, go to the Permissions tab, set the bucket to private and turn off the option that lets individual objects be made public. If the bucket hosts a public website on purpose, record it as an accepted risk.

7. lightsail.instance.admin_ports_restricted

Finding
1 admin port(s) open to the internet across 2 instance(s)
Controls
A.8.20
Affected (exposed admin ports)
  • instance: worker-1; port: 22; service: SSH; open to: 0.0.0.0/0
How to fix
In the Lightsail console open the instance, go to the Networking tab and edit the SSH (22) or RDP (3389) rule in the IPv4 firewall: restrict it to your own IP addresses, or allow only Lightsail browser SSH/RDP. Do the same in the IPv6 firewall, or turn IPv6 off if you do not use it.

8. lightsail.instance.auto_snapshots

Finding
1 of 2 instances have automatic snapshots enabled
Controls
A.8.13
Affected (instances without auto snapshots)
  • worker-1
How to fix
In the Lightsail console open the instance, go to the Snapshots tab and turn on automatic snapshots. Snapshot storage is billed per GB. If the instance holds no data you need, record that as an accepted risk instead.

9. lightsail.instance.blueprint_supported

Finding
1 of 2 instances run a retired blueprint (OS image)
Controls
A.8.8
Affected (retired blueprints)
  • instance: worker-1; blueprint: ubuntu_18_04
How to fix
The OS image is retired, which usually means the OS version is near or past end of life. Take a snapshot, create a new instance from a current blueprint, move the application and delete the old instance.

10. lightsail.instance.imdsv2_required

Finding
1 of 2 instances require IMDSv2
Controls
A.8.9
Affected (instances allowing imdsv1)
  • worker-1
How to fix
Require IMDSv2 with the AWS CLI: aws lightsail update-instance-metadata-options --instance-name <name> --http-tokens required. Test the application afterwards, because very old SDKs may still use IMDSv1.
